## 🔍 当前问题分析

**问题1：模式判断依赖路由参数，不够可靠**
```typescript
// 当前实现：依赖 fromDraft 参数
const isDraft = computed(() => route.query.fromDraft === 'true')
```
如果用户直接通过 URL 访问 `/publish/123`，无法判断该物品是草稿还是已发布。

**问题2：`isPublished` 判断不完整**
```typescript
// 当前只判断 AVAILABLE 和 BORROWED
isPublished.value = item.status === 'AVAILABLE' || item.status === 'BORROWED'
```
遗漏了 `OFFLINE` 状态。

**问题3：不同状态的编辑需求未明确**
- 下架物品编辑后是否自动上架？
- 借出中的物品是否允许编辑？

## ✅ 推荐设计方案

### 方案：基于物品实际状态驱动

**核心思想**：按钮显示由物品的 `status` 字段决定，而非路由参数。

| 物品状态 | 页面标题 | 按钮组合 | 说明 |
|---------|---------|---------|------|
| 新建（无ID） | 发布新物品 | `保存草稿` + `发布物品` | 全新创建 |
| DRAFT | 继续编辑草稿 | `保存草稿` + `发布物品` | 草稿可继续保存或发布 |
| AVAILABLE | 编辑物品 | `保存修改` | 保持在线状态 |
| BORROWED | 编辑物品 | `保存修改` | 借出中可编辑（限制某些字段？） |
| OFFLINE | 编辑物品 | `保存修改` | 保持下架状态 |

**上架/下架操作**：在个人中心进行，不放在编辑页。
