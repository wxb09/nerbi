## 分页设计模式

```
┌─────────────────────────────────────────────────────────┐
│                    页面组件 (View)                       │
│  ForumView.vue / AdminSensitiveWords.vue               │
│                                                         │
│  ┌─────────────────────────────────────────────────┐  │
│  │              usePagination (逻辑层)               │  │
│  │  - 负责请求 API                                   │  │
│  │  - 管理 loading/error/data 状态                   │  │
│  │  - 处理分页参数                                   │  │
│  │  - 提供 loadMore/refresh/goToPage 方法            │  │
│  └─────────────────────────────────────────────────┘  │
│                         │                               │
│                         │ 解构出来的状态和方法            │
│                         ▼                               │
│  ┌─────────────────────────────────────────────────┐  │
│  │            Pagination (视图层)                    │  │
│  │  - 只负责显示"上一页/页码/下一页"按钮              │  │
│  │  - 点击后调用 goToPage 方法                       │  │
│  │  - 不关心数据从哪来、如何加载                     │  │
│  └─────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 对比

| 层级 | 名称 | 类型 | 职责 |
|------|------|------|------|
| **逻辑层** | `usePagination` | 函数 (Hook) | 数据请求、状态管理、分页逻辑 |
| **视图层** | `Pagination` | 组件 (Component) | UI 展示、用户交互 |

### 好处

1. **职责分离** - 逻辑归逻辑，UI 归 UI
2. **复用性强** - 同一个 Hook 可以配不同的 UI 组件
3. **灵活性高** - 可以只用 Hook 不用组件（如 ForumView 的"加载更多"按钮）

### 使用对比

**ForumView** - 用 Hook + 自定义按钮：
```vue
<script setup>
const { hasMore, loadMore } = usePagination(...)
</script>
<template>
  <button v-if="hasMore" @click="loadMore">加载更多</button>
</template>
```

**AdminSensitiveWords** - 用 Hook + 组件：
```vue
<script setup>
const { page, totalPages, goToPage } = usePagination(...)
</script>
<template>
  <Pagination :page="page" @change="goToPage" />
</template>
```

这就是典型的 **"逻辑与视图分离"** 设计模式。
