# 借阅申诉流程

> 用户发起申诉 → 管理员处理申诉的完整流程说明

***

## 一、功能概述

借阅申诉功能允许用户在借阅完成后，对借阅过程中遇到的问题进行申诉，由管理员介入处理。

| 角色 | 功能 |
|------|------|
| 普通用户 | 在个人中心对已归还的借阅发起申诉 |
| 管理员 | 在管理后台查看申诉列表，解决/驳回申诉 |

***

## 二、用户端流程

### 2.1 入口位置

1. 用户登录后进入「个人中心」
2. 切换到「借阅记录」标签页
3. 找到状态为「已归还」的借阅记录
4. 点击右侧「更多」按钮
5. 在下拉菜单的「反馈」区域点击「申诉」

### 2.2 申诉条件

- 借阅状态必须为 `RETURNED`（已归还）
- 该借阅没有进行中的申诉

### 2.3 申诉表单

| 字段 | 说明 |
|------|------|
| 物品名称 | 自动显示（只读） |
| 对方用户 | 自动显示（只读） |
| 申诉原因 | 必填，文本域 |

### 2.4 提交后效果

1. 申诉记录创建，状态为 `PENDING`
2. 借阅状态变更为 `DISPUTED`
3. 对方用户收到系统通知：「您涉及的借阅「xxx」已被对方发起申诉，请等待管理员处理。」
4. 弹窗提示：「申诉已提交，请等待管理员处理」

***

## 三、管理员端流程

### 3.1 查看申诉列表

1. 管理员登录后自动进入管理后台
2. 点击侧边栏「借阅纠纷」
3. 默认显示「纠纷列表」标签页
4. 可按状态筛选：全部 / 待处理 / 调查中 / 已解决 / 已驳回

### 3.2 申诉列表字段

| 字段 | 说明 |
|------|------|
| 纠纷ID | 申诉记录的唯一标识 |
| 申诉人 | 发起申诉的用户昵称 |
| 物品 | 涉及的物品名称 |
| 原因 | 用户填写的申诉原因 |
| 状态 | PENDING / INVESTIGATING / RESOLVED / DISMISSED |
| 提交时间 | 申诉创建时间 |

### 3.3 处理申诉

#### 解决申诉

1. 点击申诉行的「✓」按钮
2. 弹窗显示申诉详情
3. 填写处理结果（可选）
4. 点击「确认解决」

**解决后效果**：
- 申诉状态 → `RESOLVED`
- 借阅状态 → `RETURNED`
- 物品状态 → `AVAILABLE`
- 双方收到通知：「您涉及的借阅纠纷已处理：xxx」

#### 驳回申诉

1. 点击申诉行的「✕」按钮
2. 弹窗显示申诉详情
3. 填写驳回原因（可选）
4. 点击「确认驳回」

**驳回后效果**：
- 申诉状态 → `DISMISSED`
- 借阅状态 → `ACTIVE`（继续借用）
- 双方收到通知

***

## 四、状态流转

### 4.1 申诉状态

```
PENDING → INVESTIGATING → RESOLVED
                 ↓
              DISMISSED
```

| 状态 | 说明 |
|------|------|
| PENDING | 待处理，用户刚提交 |
| INVESTIGATING | 调查中（预留，当前未使用） |
| RESOLVED | 已解决 |
| DISMISSED | 已驳回 |

### 4.2 借阅状态联动

| 操作 | 借阅状态变化 |
|------|-------------|
| 用户发起申诉 | `RETURNED` → `DISPUTED` |
| 管理员解决 | `DISPUTED` → `RETURNED` |
| 管理员驳回 | `DISPUTED` → `ACTIVE` |

***

## 五、API 接口

### 5.1 用户发起申诉

```
POST /api/disputes
Authorization: Bearer {token}

Request Body:
{
  "borrowId": 123,
  "reason": "物品归还时有损坏，但对方不承认..."
}

Response:
{
  "code": 0,
  "message": "OK"
}
```

### 5.2 管理员查询申诉列表

```
GET /api/admin/disputes?status=PENDING&page=0&size=20
Authorization: Bearer {admin_token}

Response:
{
  "code": 0,
  "data": {
    "content": [...],
    "totalElements": 10,
    "totalPages": 1
  }
}
```

### 5.3 管理员处理申诉

```
POST /api/admin/disputes/{id}/resolve
Authorization: Bearer {admin_token}

Request Body:
{
  "action": "resolve",  // 或 "dismiss"
  "resolution": "经核实，物品确实存在损坏，建议双方协商赔偿..."
}

Response:
{
  "code": 0,
  "message": "OK"
}
```

## 八、数据库表

### disputes 表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| borrow_id | BIGINT | 关联借阅 |
| reporter_id | BIGINT | 申诉人 |
| reason | VARCHAR(500) | 申诉原因 |
| status | VARCHAR(20) | 状态 |
| resolution | VARCHAR(500) | 处理结果 |
| resolved_by | BIGINT | 处理人 |
| resolved_at | TIMESTAMP | 处理时间 |
| created_at | TIMESTAMP | 创建时间 |
