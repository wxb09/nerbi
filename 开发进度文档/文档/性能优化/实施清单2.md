缓存失效策略，是最后实现的嘛

不是的，缓存失效策略不应该最后才实现。

如果先加缓存、最后才加失效，中间阶段会出现严重的数据不一致问题——用户发了新帖子但列表里看不到，体验会很差。

正确的做法是**缓存和失效配套实现**，每个阶段做缓存的同时就把对应的失效加上：

## **调整后的实施清单**

### **Phase 1：前端 API 请求缓存层**

- &#x20;新建 **`frontend/src/utils/cache.ts`**
- **`api.ts`** 集成缓存读写拦截器
- &#x20;写操作（POST/PUT/DELETE）后自动清除对应 URL 前缀的缓存（如发帖后清 **`/forum/posts`** 缓存）

### **Phase 2：localStorage 基础数据缓存**

- &#x20;新建 **`frontend/src/utils/localCache.ts`**
- &#x20;分类/社区数据接入缓存
- &#x20;管理员修改分类/社区后清除对应 localCache

### **Phase 3：usePagination 缓存增强**

- **`usePagination`** 新增 **`cacheKey`** / **`cacheTTL`**
- &#x20;首页物品列表、论坛帖子列表启用缓存
- &#x20;发布物品/帖子后调用 **`clearCache()`**

### **Phase 4：后端 Spring Cache 集成**

- &#x20;依赖 + **`@EnableCaching`** + **`CacheConfig`**
- &#x20;各 Service 加 **`@Cacheable`** 的同时加 **`@CacheEvict`**（**一起写，不拆开**）
- &#x20;联调验证：写操作后读取为最新数据

### **Phase 5：收尾与边界场景**

- &#x20;管理员批量操作的缓存清除覆盖
- &#x20;凌晨定时清理过期缓存
- &#x20;全链路回归测试

核心原则：**加缓存的那一行代码旁边，就写好失效逻辑**，不留给后面。
