### V3__Update_Reviews_Table.sql — 评价表结构重构

[文件路径](file:///d:/ai练/fast/backend/demo/src/main/resources/db/migration/V3__Update_Reviews_Table.sql)

## 三、Views 页面详解

### 1. [IndexView.vue](file:///d:/ai练/fast/frontend/src/views/IndexView.vue) — 首页（物品列表）
- **功能**：展示物品列表，支持搜索、按小区/分类筛选、分页
- **关键逻辑**：
  - 搜索防抖（500ms）
  - 调用 `itemApi.getItems()` 和 `itemApi.searchItems()` 获取数据
  - 调用 `publicApi.getCommunities()` 和 `publicApi.getCategories()` 获取筛选数据
  - 分页组件（最多显示 5 个页码）
  - 图片 URL 拼接 `http://localhost:8080/uploads/`

### 2. [LoginView.vue](file:///d:/ai练/fast/frontend/src/views/LoginView.vue) — 登录页
- **功能**：手机号 + 验证码登录
- **关键逻辑**：
  - 调用 `authApi.sendVerifyCode()` 发送验证码
  - 60 秒倒计时
  - 调用 `authApi.login()` 登录，成功后 `authStore.login()` 保存状态
  - 预填手机号 `13800002026` 和验证码 `123456`（开发用）

### 3. [DetailView.vue](file:///d:/ai练/fast/frontend/src/views/DetailView.vue) — 物品详情页
- **功能**：展示物品详情、物品故事、物品主人信息、借阅规则、申请借用
- **关键逻辑**：
  - 路由参数 `/item/:id`
  - 根据物品状态（AVAILABLE/BORROWED/OFFLINE）显示不同 UI
  - 借用申请表单：开始日期、结束日期、用途、同意条款
  - 调用 `borrowApi.createBorrow()` 提交借阅申请
  - 未登录时跳转登录页

### 4. [ForumView.vue](file:///d:/ai练/fast/frontend/src/views/ForumView.vue) — 社区论坛
- **功能**：社区动态流（感谢信、求助、分享），右侧边栏（社区公告、绿色榜、热门话题）
- **关键逻辑**：
  - 目前使用**硬编码模拟数据**，未接入后端 API
  - 支持发帖（前端本地插入）、点赞
  - 帖子类型：thanks（感谢信）、help（求助）、share（分享）
  - @提及高亮显示

### 5. [PublishView.vue](file:///d:/ai练/fast/frontend/src/views/PublishView.vue) — 发布/编辑物品
- **功能**：新建物品、编辑物品、继续编辑草稿
- **关键逻辑**：

### [websocket.ts](file:///d:/ai练/fast/frontend/src/utils/websocket.ts) — WebSocket 管理器

**类 `WebSocketManager`**，导出单例 `wsManager`：

| 方法/属性 | 说明 |
|-----------|------|
| `connect(token)` | 建立 WebSocket 连接（`ws://localhost:8080/ws/message?token={token}`） |
| `disconnect()` | 断开连接 |
| `isConnected()` | 检查连接状态 |
| `send(message)` | 发送 JSON 消息 |
| `on(type, handler)` | 注册消息处理器（支持通配符 `*`） |
| `off(type, handler)` | 注销消息处理器 |

**核心机制**：
- **心跳**：每 30 秒发送 `{ type: 'PING' }`
- **自动重连**：最多 5 次，间隔 3 秒
- **消息分发**：按 `message.type` 分发给注册的处理器，支持 `*` 通配符
- 登录时自动连接，登出时自动断开

## 十一、业务流程总结

```
登录 → 首页浏览物品 → 查看详情 → 申请借阅
                         ↓
                    物品主人审批 → 借入者确认取件 → 使用中 → 申请归还 → 物品主人确认归还 → 双方互评
                         ↓
                    发布物品（可保存草稿）→ 上架/下架管理
                         ↓
                    消息中心（WebSocket 实时推送）
                         ↓
                    管理后台（数据仪表盘、审核管理）
```

**核心业务实体**：物品(Item)、借阅(Borrow)、评价(Review)、消息(Message)、用户(User)

**借阅状态流转**：`PENDING` → `APPROVED` → `ACTIVE` → `RETURN_REQUESTED` → `RETURNED`（也可 `REJECTED`/`CANCELLED`/`OVERDUE`）

**物品状态**：`DRAFT` → `AVAILABLE` → `BORROWED` → `OFFLINE`

## 一、项目概览

这是一个基于 **Spring Boot + JPA + MySQL** 的社区物品共享平台后端，核心功能是邻里之间的物品借用、归还、评价和消息通知。项目使用 Flyway 管理数据库迁移，WebSocket 实现实时推送，JWT 实现认证。

当前 JWT 中已有 `role` 字段（[JwtService.java:32](file:///d:/ai练/fast/backend/demo/src/main/java/com/neighbor/auth/JwtService.java#L32)），但存在以下问题：

- **数据库 `users` 表没有 `role` 列** — V1 迁移脚本中没有定义
- **登录时硬编码 `"user"`** — [AuthService.java:60](file:///d:/ai练/fast/backend/demo/src/main/java/com/neighbor/auth/AuthService.java#L60) 写死 `jwtService.generateToken(..., "user")`
- **`AuthUser` record 有 `role` 字段** — [AuthUser.java](file:///d:/ai练/fast/backend/demo/src/main/java/com/neighbor/auth/AuthUser.java) 但从未用于权限校验
- **SecurityConfig 没有角色区分** — [SecurityConfig.java](file:///d:/ai练/fast/backend/demo/src/main/java/com/neighbor/config/SecurityConfig.java) 只有 `permitAll()` 和 `authenticated()`，无 `hasRole()`
- **前端 `/admin` 路由无需认证** — [router/index.ts:27](file:///d:/ai练/fast/frontend/src/router/index.ts#L27) 没有 `meta.requiresAuth`

### 2. UserStatus 枚举 — 已就绪

[UserStatus.java](file:///d:/ai练/fast/backend/demo/src/main/java/com/neighbor/enums/UserStatus.java) 已定义 `ACTIVE`/`BANNED`/`DELETED`，但当前没有任何业务逻辑使用 BANNED 状态（登录时也不检查用户状态）。

### 3. AdminView.vue — 纯 UI 壳

[AdminView.vue](file:///d:/ai练/fast/frontend/src/views/AdminView.vue) 有完整的侧边栏导航和仪表盘 UI，但 **全部数据是硬编码**，没有任何 API 调用。侧边栏已规划了：
- 数据仪表盘 / 物品管理 / 借阅审核 / 用户管理 / 帖子管理 / 公告发布 / 绿色榜单 / 系统设置 / 权限管理

### 4. 物品审核 — 需要新增状态

当前物品状态流转是 `DRAFT → AVAILABLE → BORROWED → AVAILABLE`（下架 `OFFLINE`），**没有"待审核"状态**。物品发布后直接变为 AVAILABLE，缺少管理员审核环节。

### 5. 借阅纠纷 — 需要新增机制

当前借阅状态有 `OVERDUE`（超期），但没有纠纷状态和纠纷处理流程。需要新增纠纷提交和管理员介入机制。

### 四大功能模块拆解

#### ① 用户管理（封禁/解封）

- 管理员查看用户列表（分页、搜索、按状态筛选）
- 封禁用户：修改 `status` → `BANNED`，强制下线（踢出 WebSocket）
- 解封用户：修改 `status` → `ACTIVE`
- 封禁时自动下架该用户所有 AVAILABLE 物品
- 登录时检查 BANNED 状态，拒绝登录

#### ② 物品审核

- 方案选择：新增 `PENDING_REVIEW` 状态 vs 新增 `audit_status` 字段
- 物品发布后先进入待审核状态，管理员审核通过后才变为 AVAILABLE
- 管理员可查看待审核物品列表、通过/驳回（附原因）
- 驳回后通知物品所有者

#### ③ 借阅纠纷处理

- 方案选择：`BorrowStatus` 增加 `DISPUTED` vs 新建 `disputes` 表
- 借阅双方可发起纠纷申诉
- 管理员查看纠纷列表，介入处理（强制归还、信用惩罚等）
- 处理结果通知双方

#### ④ 数据统计

- 平台总物品数、总用户数、总借阅次数
- 本月新增趋势（物品/用户/借阅）
- 碳减排累计统计
- 各分类物品分布
- 借阅状态分布
- 用户信用分布
