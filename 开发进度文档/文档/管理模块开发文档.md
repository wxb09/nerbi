## 四、物品状态流转（更新）

```
DRAFT → PENDING_REVIEW → AVAILABLE → BORROWED → AVAILABLE
              ↓              ↓
            DRAFT         OFFLINE → AVAILABLE
```

| 状态 | 说明 |
|------|------|
| DRAFT | 草稿 |
| PENDING_REVIEW | 待审核（新增） |
| AVAILABLE | 可借 |
| BORROWED | 借出中 |
| OFFLINE | 已下架 |
| DELETED | 已删除 |

**关键变更**：物品发布后不再直接变为 AVAILABLE，而是先进入 PENDING_REVIEW，管理员审核通过后才上架。

***

## 五、借阅状态流转（更新）

```
PENDING → APPROVED → ACTIVE → RETURN_REQUESTED → RETURNED
    ↓                   ↓
REJECTED            DISPUTED → RETURNED / ACTIVE
```

| 新增状态 | 说明 |
|----------|------|
| DISPUTED | 纠纷中，管理员介入处理 |

## 六、后端 API 接口

所有管理接口路径为 `/api/admin/**`，需 JWT 认证且 role=ADMIN。

### 6.1 数据统计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/stats` | 获取平台统计数据 |

响应字段：totalUsers, totalItems, totalBorrows, pendingReviewItems, activeBorrows, pendingDisputes, bannedUsers, thisMonthUsers, thisMonthBorrows

### 6.2 用户管理

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/users` | 用户列表（支持 keyword/status/role 筛选） |
| POST | `/api/admin/users/{id}/ban` | 封禁用户 |
| POST | `/api/admin/users/{id}/unban` | 解封用户 |

**封禁逻辑**：
1. 修改用户状态为 BANNED
2. 自动下架该用户所有 AVAILABLE 物品（→ OFFLINE）
3. 发送系统通知
4. 后续登录时拦截 BANNED 状态

### 6.3 物品审核

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/items/pending-review` | 待审核物品列表 |
| GET | `/api/admin/items` | 全部物品列表（支持 status 筛选） |
| POST | `/api/admin/items/{id}/audit` | 审核物品 |

审核请求体：`{ "action": "approve" | "reject", "remark": "可选备注" }`

**审核逻辑**：
- approve → PENDING_REVIEW → AVAILABLE，通知物品所有者审核通过
- reject → PENDING_REVIEW → DRAFT，通知物品所有者审核未通过（附原因）

### 6.4 借阅纠纷

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/borrows` | 借阅记录列表（支持 status 筛选） |
| POST | `/api/admin/disputes` | 发起纠纷 |
| GET | `/api/admin/disputes` | 纠纷列表（支持 status 筛选） |
| POST | `/api/admin/disputes/{id}/resolve` | 处理纠纷 |

发起纠纷请求体：`{ "borrowId": 1, "reason": "纠纷原因" }`

处理纠纷请求体：`{ "action": "resolve" | "dismiss", "resolution": "处理结果" }`

**纠纷处理逻辑**：
- resolve → 借阅状态→RETURNED，物品→AVAILABLE，通知双方
- dismiss → 借阅状态→ACTIVE（继续借用），通知双方

## 九、交互设计

所有管理操作使用内联弹窗（Modal）交互，不使用浏览器原生 `confirm`/`prompt`/`alert`：

- **封禁/解封**：确认弹窗，显示用户信息和操作后果提示
- **审核通过**：弹窗可填写审核备注（可选）
- **审核驳回**：弹窗必填驳回原因
- **发起纠纷**：弹窗必填纠纷原因
- **解决/驳回纠纷**：弹窗显示纠纷详情，可填写处理结果
- **操作反馈**：右上角 Toast 提示（成功/失败）
