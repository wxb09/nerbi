## 已解决问题记录

### 草稿功能设计

**问题**：编辑页无法区分草稿和已发布物品

**解决**：基于物品实际状态判断模式
- `isNew`: 无 ID 参数 → 新建模式
- `isDraft`: 状态 = DRAFT → 草稿编辑
- `isEdit`: 有 ID 且非草稿 → 已发布编辑

### BORROWED 状态禁止编辑

**问题**：借出中的物品不应允许编辑

**解决**：
- 后端：`deleteItem` 校验 `status != BORROWED`
- 前端：编辑按钮 `disabled` 状态
- 双重校验确保安全

### 图片重复添加问题

**问题**：保存物品时图片重复添加

**原因**：
1. JPA 实体缺少 `orphanRemoval = true`
2. 空列表时 `clear()` 不执行

**解决**：
- `Item.java` 添加 `orphanRemoval = true`
- `ItemServiceImpl.java` 将 `clear()` 移到外层

### 上架功能失效

**问题**：下架物品无法上架，草稿无法发布

**原因**：后端 `populateItemFromData` 未处理 `status` 字段

**解决**：添加 status 字段处理逻辑

### 消息模块设计

#### 消息类型

| 类型 | 触发方式 | 发送者 | 接收者 |
|-----|---------|-------|-------|
| 借阅申请 | 主动 | 借阅者 | 物主 |
| 申请结果 | 自动 | 系统 | 借阅者 |
| 即将到期 | 定时任务 | 系统 | 借阅者 |
| 已超期 | 定时任务 | 系统 | 借阅者+物主 |
| 归还确认 | 自动 | 系统 | 借阅者 |
| 收到评价 | 自动 | 系统 | 被评价者 |
| 审核通知 | 自动 | 系统 | 用户 |
| 用户私信 | 主动 | 用户 | 用户 |

#### 数据结构

```sql
-- 方案A：单表设计（简单）
CREATE TABLE messages (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    sender_id BIGINT,           -- NULL = 系统消息
    receiver_id BIGINT NOT NULL,
    type VARCHAR(20),           -- BORROW_APPLY/EXPIRING/EXPIRED/...
    title VARCHAR(100),
    content TEXT,
    related_type VARCHAR(20),   -- ITEM/BORROW/REVIEW
    related_id BIGINT,
    is_read BOOLEAN DEFAULT FALSE,
    created_at DATETIME
);

-- 方案B：分类表设计（扩展性好）
CREATE TABLE notifications (...);
CREATE TABLE private_messages (...);
CREATE TABLE conversations (...);
```
