# 邻里共享平台 - 接口规范

> 本文档定义了前后端数据交互的接口规范，确保数据格式一致性

---

## 📋 数据格式规范

### 1. 数组字段处理

**规范**：前端发送 JSON 字符串，后端接收并解析

#### 适用字段

| 字段名 | 类型 | 说明 | 示例 |
|--------|------|------|------|
| `returnRequirements` | `List<String>` | 归还要求 | `["已消毒", "保持原样"]` |
| `tags` | `List<String>` | 物品标签 | `["专业工具", "露营"]` |
| `images` | `List<String>` | 图片 URL 列表 | `["items/uuid1.jpg", "items/uuid2.jpg"]` |

---

## 🔧 前端实现

### 发送数据时

```typescript
// ❌ 错误：直接发送数组
const itemData = {
  name: '电钻',
  returnRequirements: ['已消毒', '保持原样'],
  tags: ['专业工具', '露营']
}

// ✅ 正确：数组转为 JSON 字符串
const itemData = {
  name: '电钻',
  returnRequirements: JSON.stringify(['已消毒', '保持原样']),
  tags: JSON.stringify(['专业工具', '露营'])
}

await itemApi.createItem(itemData)
```

### 接收数据时

```typescript
// 后端返回的已经是解析后的数组，直接使用
const item = await itemApi.getItemById(id)
console.log(item.returnRequirements) // ['已消毒', '保持原样']
console.log(item.tags) // ['专业工具', '露营']
```

## 🛠️ 后端实现

### 接收数据时

```java
public Long createItem(CreateItemRequest request) {
    // 方法 1：使用 Map 接收，手动解析
    Map<String, Object> data = request.getData();
    
    if (data.containsKey("returnRequirements")) {
        String returnRequirementsJson = (String) data.get("returnRequirements");
        List<String> returnRequirements = parseJsonToList(returnRequirementsJson);
        item.setReturnRequirements(returnRequirementsJson); // 存储 JSON 字符串
    }
    
    if (data.containsKey("tags")) {
        String tagsJson = (String) data.get("tags");
        item.setTags(tagsJson); // 存储 JSON 字符串
    }
    
    // 方法 2：使用 Record 接收，自动解析（推荐）
    // CreateItemRequest 中定义：
    // String returnRequirements; // JSON 字符串
    // String tags; // JSON 字符串
}

// 工具方法：JSON 字符串转 List
private List<String> parseJsonToList(String json) {
    try {
        return mapper.readValue(json, new TypeReference<List<String>>() {});
    } catch (Exception e) {
        return Collections.emptyList();
    }
}
```

### 返回数据时

```java
public ItemDetailDTO getItemById(Long id) {
    Item item = itemRepository.findById(id).orElseThrow(...);
    
    // 从 JSON 字符串解析为 List
    List<String> returnRequirements = parseJsonToList(item.getReturnRequirements());
    List<String> tags = parseJsonToList(item.getTags());
    
    return new ItemDetailDTO(
        item.getId(),
        item.getName(),
        // ... 其他字段
        returnRequirements, // 直接返回 List，Jackson 会自动序列化
        tags
    );
}
```

## 📊 数据库存储

### 字段类型

| 字段 | 数据库类型 | 存储格式 | 示例 |
|------|-----------|---------|------|
| `return_requirements` | TEXT | JSON 数组字符串 | `["已消毒","保持原样"]` |
| `tags` | VARCHAR(500) | JSON 数组字符串 | `["专业工具","露营"]` |

### SQL 示例

```sql
-- 插入数据
INSERT INTO items (name, return_requirements, tags) 
VALUES ('电钻', '["已消毒","保持原样"]', '["专业工具","露营"]');

-- 查询数据
SELECT name, return_requirements, tags FROM items WHERE id = 1;
-- 返回：
-- name: 电钻
-- return_requirements: ["已消毒","保持原样"]
-- tags: ["专业工具","露营"]
```

public ApiResponse<Long> createItem(@RequestBody CreateItemRequest request) {
    Long itemId = itemService.createItem(request);

// Service 层
public Long createItem(CreateItemRequest request) {

}

## ⚠️ 常见错误

### 错误 1：前端直接发送数组

```typescript
// ❌ 错误
const itemData = {
  returnRequirements: ['已消毒'], // 数组
  tags: ['专业工具'] // 数组
}
```

**后果**：后端无法解析，抛出异常

---

### 错误 2：后端未解析直接使用

```java
// ❌ 错误
String returnRequirements = (String) data.get("returnRequirements");
item.setReturnRequirements(returnRequirements); // 直接存储
```

**后果**：存储的是字符串字面量，不是 JSON 数组

---

### 错误 3：图片路径格式不一致

```typescript
// ❌ 错误：前端添加完整 URL
const images = ['http://localhost:8080/uploads/items/uuid.jpg']

// ✅ 正确：存储相对路径
const images = ['items/uuid.jpg']
```

**原因**：后端会统一处理图片路径，前端只需存储相对路径

## 📝 总结

### 核心原则

1. **前端发送**：数组 → JSON.stringify() → 字符串
2. **后端接收**：字符串 → 存储到数据库
3. **后端返回**：数据库字符串 → 解析为 List → DTO
4. **前端接收**：直接使用 List

### 记忆口诀

> 前送字，后存字，后返列，前用列
