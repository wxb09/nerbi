## 集群和 Redis 概念解释

---

### 一、什么是集群？

**集群 = 多台服务器一起工作**

```
单机部署：
┌─────────────────┐
│   一台服务器     │ ← 用户请求
│   Spring Boot   │
└─────────────────┘

集群部署：
┌─────────────────┐
│   服务器 1       │
│   Spring Boot   │
└─────────────────┘
        ↑
用户请求 → 负载均衡器
        ↓
┌─────────────────┐
│   服务器 2       │
│   Spring Boot   │
└─────────────────┘
        ↓
┌─────────────────┐
│   服务器 3       │
│   Spring Boot   │
└─────────────────┘
```

---

### 二、为什么要集群？

| 问题 | 单机 | 集群 |
|-----|------|------|
| **用户多了卡顿** | 一台服务器扛不住 | 多台分担压力 |
| **服务器挂了** | 整个网站瘫痪 | 其他服务器继续工作 |
| **需要维护升级** | 必须停服 | 一台一台升级，用户无感知 |

**简单比喻**：
- 单机 = 一个服务员招待所有客人
- 集群 = 多个服务员分工合作

---

### 三、什么是 Redis？

**Redis = 内存数据库，超快的缓存**

```
传统数据库：
用户请求 → 服务器 → MySQL（硬盘） → 返回结果
                        ↑
                    读写慢（毫秒级）

Redis 缓存：
用户请求 → 服务器 → Redis（内存） → 返回结果
                        ↑
                    读写快（微秒级）
```

---

### 四、Redis 能做什么？

| 功能 | 说明 | 例子 |
|-----|------|------|
| **缓存** | 存热点数据，减轻数据库压力 | 用户信息、商品详情 |
| **会话存储** | 存用户登录状态 | 分布式 Session |
| **消息队列** | 异步处理任务 | 订单通知、短信发送 |
| **排行榜** | 实时排名 | 游戏积分榜 |
| **计数器** | 高频计数 | 点赞数、浏览量 |
| **发布订阅** | 消息广播 | **WebSocket 集群通信** |

---

### 五、集群 + WebSocket 的问题

**场景**：用户 A 连接到了服务器 1，消息在服务器 2 产生

```
用户 A ──WebSocket──→ 服务器 1
                        │
                        │  没有用户 A 的连接！
                        ↓
                    服务器 2 ← 定时任务产生消息
                        │
                        ✗ 无法推送给用户 A
```

**解决方案：Redis 发布订阅**

```
用户 A ──WebSocket──→ 服务器 1 ←──┐
                        │        │
                    订阅消息     │ Redis
                        │        │ 发布消息
                        ↓        │
                    服务器 2 ────┘
                        ↑
                    定时任务产生消息
```

**流程**：
1. 服务器 2 产生消息 → 发布到 Redis
2. Redis 广播给所有订阅的服务器
3. 服务器 1 收到消息 → 推送给用户 A

---

### 六、总结对比

| 概念 | 是什么 | 解决什么问题 |
|-----|--------|------------|
| **集群** | 多台服务器一起工作 | 高并发、高可用 |
| **Redis** | 内存数据库/缓存 | 快速读写、数据共享 |
| **Redis Pub/Sub** | 消息发布订阅 | 集群间通信 |

---

### 七、你的项目需要吗？

| 场景 | 是否需要 |
|-----|:-------:|
| 用户量 < 1000，单机部署 | ❌ 不需要 |
| 用户量 > 10000，需要集群 | ✅ 需要 Redis |
| 追求 WebSocket 实时推送体验 | ⚠️ 单机可直接做，集群需要 Redis |

**当前项目**：邻里共享平台，规模较小，**单机部署足够**，暂不需要考虑集群和 Redis。
