# 审核与举报系统重构文档

> 最后更新：2026-04-22

---

## 一、重构背景

### 原有问题

1. **posts/comments 表的 `audit_status` 和 `audit_reason` 字段冗余**
   - 拦截时帖子不保存，这两个字段永远不会被持久化
   - 通过时 `audit_status=1`，但这个状态没有实际意义

2. **审核日志表职责单一**
   - 只记录自动审核（敏感词拦截）
   - 举报需要新增表，导致表结构混乱

3. **状态流转不清晰**
   - 帖子状态、审核状态、举报状态分散在不同表

---

## 二、重构方案

### 核心思路

**统一审核记录表，简化业务表**

```
旧方案：                    新方案：
posts                       posts
├── audit_status  ❌删除    ├── status (PUBLISHED/DELETED/UNDER_REVIEW)
└── audit_reason  ❌删除    └── ...

comments                    comments
├── audit_status  ❌删除    ├── status
└── audit_reason  ❌删除    └── ...

audit_logs        扩展      audit_logs (统一审核记录)
├── target_type             ├── target_type
├── target_id               ├── target_id
├── audit_result            ├── review_type (AUTO/REPORT) ⭐新增
├── ...                     ├── audit_result
                            ├── reporter_id ⭐新增
                            ├── handler_id ⭐新增
                            └── result ⭐新增

post_reports      ❌不新增   (合并到 audit_logs)
```

## 三、数据库变更

### 迁移脚本 V13

```sql
-- 1. 删除冗余字段
ALTER TABLE posts DROP COLUMN audit_status;
ALTER TABLE posts DROP COLUMN audit_reason;
ALTER TABLE comments DROP COLUMN audit_status;
ALTER TABLE comments DROP COLUMN audit_reason;

-- 2. 扩展审核日志表
ALTER TABLE audit_logs
    ADD COLUMN review_type VARCHAR(20) DEFAULT 'AUTO',
    ADD COLUMN reporter_id BIGINT NULL,
    ADD COLUMN handler_id BIGINT NULL,
    ADD COLUMN result TEXT;

-- 3. 添加索引
CREATE INDEX idx_review_type ON audit_logs(review_type);
CREATE INDEX idx_reporter ON audit_logs(reporter_id);
```

## 四、状态流转

### 自动审核流程

```
用户发帖
    ↓
敏感词检测
    ↓
├─ 发现敏感词 → 记录 audit_logs (review_type=AUTO, audit_result=BLOCK)
│              → 抛出异常，帖子不保存
│
└─ 未发现问题 → 帖子正常保存 (status=PUBLISHED)
               → 不记录日志（通过不记录）
```

### 举报流程

```
用户举报帖子
    ↓
创建 audit_logs 记录
    review_type=REPORT
    audit_result=PENDING
    reporter_id=当前用户ID
    result=举报原因
    ↓
帖子状态改为 UNDER_REVIEW
    ↓
管理员处理
    ↓
├─ 删除内容 → audit_result=RESOLVED
│           → 帖子 status=DELETED
│           → handler_id=管理员ID
│
└─ 驳回举报 → audit_result=REJECTED
            → 帖子 status=PUBLISHED
            → handler_id=管理员ID
```

## 八、设计优势

| 维度 | 旧方案 | 新方案 |
|-----|-------|-------|
| 表数量 | 3张（posts, audit_logs, post_reports） | 2张（posts, audit_logs） |
| 字段冗余 | audit_status 永远为1 | 已删除 |
| 扩展性 | 每种审核类型需新表 | 加 review_type 即可 |
| 查询效率 | 需关联多张表 | 单表查询 |
| 状态清晰 | 分散在多个字段 | 统一在 audit_result |

---

> 重构后审核系统职责清晰：
> - **posts/comments**：只存业务状态（PUBLISHED/DELETED/UNDER_REVIEW）
> - **audit_logs**：统一记录所有审核事件（自动审核+用户举报+管理员处理）
