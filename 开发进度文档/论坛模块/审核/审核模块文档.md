# 论坛内容审核模块

## 一、功能概述

本模块实现了论坛内容的敏感词审核功能，基于开源库 [sensitive-word](https://github.com/houbb/sensitive-word) 实现，支持：

- 敏感词检测与拦截
- 管理员可开启/关闭审核功能
- 敏感词库管理（增删改查）
- 审核日志记录
  ### 核心特性
  1. 敏感词检测 ：DFA算法，毫秒级响应
  2. 审核开关 ：管理员可动态开启/关闭
  3. 敏感词管理 ：增删改查、启用/禁用
  4. 审核日志 ：记录所有拦截记录
  5. 权限控制 ：仅管理员可访问审核管理接口
  6. 定时刷新 ：每分钟自动刷新敏感词缓存

### 2.2 技术栈

| 组件    | 技术                    | 说明          |

## 三、数据库设计

### 3.1 敏感词表 (sensitive\_words)

| 字段          | 类型           | 说明                                |
| ----------- | ------------ | --------------------------------- |
| id          | BIGINT       | 主键                                |
| word        | VARCHAR(100) | 敏感词（唯一）                           |
| category    | VARCHAR(50)  | 分类：INSULT/PORN/POLITICAL/AD/OTHER |
| severity    | INT          | 严重程度：1-低 2-中 3-高                  |
| status      | TINYINT      | 状态：0-禁用 1-启用                      |
| created\_at | DATETIME     | 创建时间                              |
| updated\_at | DATETIME     | 更新时间                              |

### 3.2 审核日志表 (audit\_logs)

| 字段                | 类型          | 说明                |
| ----------------- | ----------- | ----------------- |
| id                | BIGINT      | 主键                |
| target\_type      | VARCHAR(20) | 目标类型：POST/COMMENT |
| target\_id        | BIGINT      | 目标ID              |
| content\_snapshot | TEXT        | 内容快照              |
| audit\_result     | VARCHAR(20) | 审核结果：PASS/BLOCK   |
| sensitive\_words  | TEXT        | 检测到的敏感词           |
| created\_at       | DATETIME    | 创建时间              |

### 3.3 帖子/评论表扩展

posts 和 comments 表新增字段：

| 字段            | 类型           | 说明                     |
| ------------- | ------------ | ---------------------- |
| audit\_status | TINYINT      | 审核状态：0-待审核 1-已通过 2-已拦截 |
| audit\_reason | VARCHAR(255) | 审核原因                   |

## 四、API 接口

### 4.1 审核开关

```
GET  /api/admin/audit/status     # 获取审核开关状态
POST /api/admin/audit/status?enabled=true/false  # 设置审核开关
```

### 4.2 敏感词管理

```
GET    /api/admin/audit/words              # 获取敏感词列表（支持分页、搜索）
POST   /api/admin/audit/words              # 添加敏感词
DELETE /api/admin/audit/words/{id}         # 删除敏感词
PUT    /api/admin/audit/words/{id}/toggle  # 启用/禁用敏感词
GET    /api/admin/audit/categories         # 获取敏感词分类列表
POST   /api/admin/audit/refresh            # 手动刷新敏感词缓存
```

### 4.3 请求示例

**添加敏感词：**

```json
POST /api/admin/audit/words
{
    "word": "测试敏感词",
    "category": "INSULT",
    "severity": 2
}
```

**获取敏感词列表：**

```
GET /api/admin/audit/words?keyword=测试&category=INSULT&page=0&size=20
```

## 五、审核流程

### 5.1 发帖审核流程

```
用户发帖 → 敏感词检测 → 检测通过？
                           ↓是          ↓否
                      保存帖子      抛出异常
                      audit_status=1  "内容包含敏感词，请修改后重试"
```

### 5.2 评论审核流程

与发帖流程相同，在 `CommentService.createComment()` 中集成。

### 5.3 审核时机

- 发帖时：审核标题 + 内容
- 评论时：审核评论内容

## 六、敏感词分类

## 七、扩展性设计

### 7.1 接入大模型

当前架构支持轻松接入大模型审核：

```java
// TextAuditService 扩展示例
public AuditResult audit(String text) {
    // 第一层：本地敏感词（已有）
    AuditResult result = sensitiveWordFilter.filter(text);
    if (result.isViolation()) return result;
    
    // 第二层：大模型审核（未来扩展）
    // result = llmAuditClient.audit(text);
    
    return AuditResult.pass();
}
```

只需新增 `LlmAuditClient` 类，实现调用 OpenAI/本地模型 即可。

### 7.2 接入云服务

可扩展接入阿里云内容安全、腾讯云天御等云服务：

```java
// 预留接口
public interface AuditClient {
    AuditResult audit(String text);
    AuditResult auditImage(String imageUrl);
}
```

### 7.3 异步审核

当前为同步审核，未来可改为异步：

```
发帖 → 落库（待审核状态）→ 发送MQ → 消费者审核 → 更新状态
```


## 九、使用说明

### 9.1 管理员操作

1. 登录管理员账号
2. 访问审核管理接口
3. 添加/管理敏感词
4. 可随时开启/关闭审核功能

### 9.2 用户操作

1. 正常发帖/评论
2. 如内容包含敏感词，系统返回错误提示
3. 修改内容后重新提交

## 十、注意事项

1. **权限控制**：所有审核管理接口仅限管理员访问
2. **缓存刷新**：敏感词变更后自动刷新缓存，也可手动刷新
3. **日志记录**：所有拦截记录保存在 audit\_logs 表
4. **性能**：DFA算法，毫秒级响应，不影响用户体验
